# Agent-first search strategy (proposal)

Status: design only. No API or code change is approved by this document.

## Evidence and problem

- `mdkb search --scope text` queries extracted AST values in `code_literals`. It does not search arbitrary source text. A query for a function name can return no hit even when the source file is indexed. `--scope symbols` searches definitions; `mdkb code find` finds an exact symbol. These are different tasks.
- The literal result prints the minimum `code_files.indexed_at`, even on no match. This number cannot prove whether the requested file is current. The CLI reads the index without a scan. The daemon watcher updates changed files after an asynchronous batch; its bootstrap scans only an empty code index.
- CLI search offers literals, including in its default result. MCP search does not offer the literal scope and its default is different. MCP base instructions still direct literal searches to Grep. `mdkb surface` documents this difference.
- The CLI accepts one positional query. A pipe is a literal character in a literal query, not OR. Multiple alternatives require multiple calls today.
- The reported `parse_subcommand` call in the ego repository was not replayed in that repository. Local source and CLI probes demonstrate the same corpus mismatch for a function name in this checkout. Do not assign the reported call a unique root cause without examining its repository and index.

## Public contract by task

| Agent task | Command family | Coverage promise |
| --- | --- | --- |
| Find an exact definition | `mdkb code find NAME` | Indexed symbol definitions; not all textual uses. |
| Find a definition with uncertain spelling | `mdkb search NAME --scope symbols` | Indexed symbol names; not arbitrary source text. |
| Find a declaration and every current use, including comments, or several alternatives | `mdkb search --scope source` | Live, eligible source files. State exclusions and partial scans; a definition-only lookup is not a substitute. |
| Find a UI label or other parsed value | `mdkb search VALUE --scope literals` | Indexed AST values; not identifiers, comments, or all source lines. |
| Find code by behavior | `mdkb search IDEA --scope semantic-code` | Semantic symbol results; not an exhaustive literal match. |
| Find project knowledge | `mdkb search IDEA --scope knowledge`, `--scope docs`, or `--scope memory` | The named knowledge corpus; do not imply source coverage. |
| Find callers or impact | `mdkb code callers` or `mdkb code impact` | Graph edges, not exhaustive lexical references. If names collide, require disambiguation rather than choosing one silently. |
| Find code duplication | `mdkb dup` | Structural duplicate sweep; not a query for matching source lines. |
| Find code-change coupling | `mdkb coupling` | Git-history audit; CLI `search --scope coupling` remains a legacy alias. No public MCP equivalent exists; say so rather than invent a tool. |

Existing spelling inventory: `mdkb code search QUERY` is the same fuzzy-symbol path as `mdkb search QUERY --scope symbols`; `mdkb memory search QUERY` selects the memory corpus. CLI `search --scope coupling` is a code-coupling audit, not a retrieval query, and is not an MCP search scope. Preserve it as an audit command with its old behavior. CLI `-i` currently applies to the indexed-literal leg and must retain that legacy behavior. Canonical source and literals accept `-i` for case-insensitive substring matching; source `--regex -i` uses case-insensitive regex matching. Test each separately, including non-ASCII cases and legacy default behavior. Keep these behaviors as deprecated entry points if they are not canonical. The MCP duplicate audit remains in `search(scope="duplicates")`, as a named audit exception beside the seven retrieval scopes. Today MCP requires a dummy query that is ignored regardless of its value; the proposed canonical MCP call omits query while existing calls with empty or nonempty query continue to work. Legacy CLI `mdkb search QUERY --scope duplicates` is different: when `--file` is absent, a nonempty QUERY is a path prefix, while `--file` takes precedence; retain this behavior. Announce this exception in the tool schema rather than teaching an agent to invent a search term.

**Teach only the clear contract while preserving old calls temporarily.** New CLI and MCP examples always supply an explicit `--scope` or `scope` from one canonical vocabulary: `source` (live occurrences), `literals` (indexed AST values), `symbols` (definitions), `semantic-code` (concept search), `docs`, `memory`, and `knowledge` (docs + memory). This is the retrieval vocabulary; the existing `duplicates` audit scope stays supported and announced separately until its placement is reviewed. Canonical retrieval calls never use the bare search's hidden docs + memory + literals mixture. For CLI, keep legacy `text` and `strings` mapped to AST literals, legacy `code` mapped to semantic code, and an omitted scope mapped to docs + memory + literals. For MCP, keep legacy `code` mapped to semantic code and an omitted scope mapped to docs + memory; MCP never accepted `text` or `strings`, so those remain rejected until the new canonical `literals` scope ships. Preserve transport-specific symbol root behavior: MCP `search(scope="symbols", root="*")` fans out with its existing per-repository hit selection and merge; CLI `--scope symbols --root '*'`, CLI comma-separated roots, and MCP comma-separated roots currently fail closed and must continue to do so. Do not infer CLI or comma-list support from the MCP wildcard route. Existing MCP filters that are ignored outside their applicable scope remain ignored on previously accepted calls, with a deprecation notice; strict incompatible-filter rejection applies only to new canonical-only parameters and forms. Preserve the same distinction for CLI options already ignored by a legacy command. Never silently repoint an old command to a new corpus. Accept previously valid old commands during the migration window and mark their use `DEPRECATED` with the searched corpus and migration guidance. Name an equivalent replacement only when there is one. An omitted CLI scope has no one-call equivalent: it searched docs + memory + literals together, while `--scope knowledge` omits literals. Its notice says `No single equivalent; choose --scope knowledge for project knowledge or --scope literals for parsed values; use both calls if both corpora are required.` Two calls do not preserve the old mixed ranking or global limit. New help, schema descriptions/examples, cheatsheet, and agent instructions show only canonical forms; do not recommend the aliases. Keep the wire-level MCP `scope` optional and parse legacy strings until sunset: an enum that rejects them at client validation would break compatibility before the server can warn. Document the canonical values without claiming they are the only wire-accepted values during migration. Keep `mdkb code find` because its exact-definition purpose is clear, not merely because it existed. CLI and MCP should align the explicit new forms while old defaults retain their existing behavior until a reviewed sunset.

### Proposed occurrence call

```sh
mdkb search --scope source -e 'emulate Claude Code' \
  -e 'Claude Code extension' -e 'claude-code' \
  --path crates/ego-cli/src/repl --root . --limit 20 --format json
```

`source` matches literal substrings by default. Only `source` may opt into `--regex` in this contract. A positional query or repeated `-e` values may be supplied, not both. Repeated `-e` values mean OR. A `|` inside a literal pattern stays literal. Return source lines in stable repository/path/line order, once per file+line (even if patterns overlap), with sorted matching pattern indexes, first matching column, one global limit, and an accurate `truncated` flag. Literal hits use AST-node locations instead: two different values on one line are two hits. Canonical source lines and AST-literal start locations use 1-based lines and 1-based UTF-8 byte columns; keep legacy outputs and daemon symbol-location conventions unchanged. Search is line-oriented: reject a source pattern containing a newline, strip CRLF terminators before matching, and reject a regex that matches an empty string. An AST literal may contain a newline, but it remains one value at its starting location; JSON must escape its content. Skip binary/invalid-UTF-8 files with an explicit partial-coverage reason. Duplicate input patterns retain their input indexes in sorted `matched_patterns`, while a source line is still one hit. Reject unsupported options before reading files. For source, literals, symbols, and exact definition, `--path` names an exact file or a directory-boundary prefix within the selected repository; it is not a substring or a glob. For duplicate audits alone, `--path` is the legacy raw `starts_with` file-path prefix: `src/cli` can match `src/cli.rs`. Keep legacy `--file` with its existing scope-specific semantics; never reinterpret a substring filter as a path prefix. For symbol/literal/code-find substring filters, the exact replacement is a separately named `--path-contains`; for a duplicate-audit raw-prefix filter, it is `--path`. The deprecation notice must name the command-specific replacement and preserve matches. Provide a distinct glob option only if measured tasks need it.

| Call relationships | Proposed `mdkb code callers NAME --root REPO [--symbol-id ID]`, or `code calls` / `code impact` with the same selection | Existing `code_graph(name=..., root=REPO, direction="callers"|"calls"|"impact", symbol_id=ID)` | Indexed graph evidence; not every textual reference. | Duplicate audit | Existing `mdkb dup` | Proposed canonical `search(scope="duplicates")` without query; today MCP requires a query but ignores every value, empty or nonempty. | Keep the audit scope in MCP and permit an omitted query only here; do not confuse a duplicate sweep with occurrence search. Old MCP calls with any query value keep working; on CLI, old `search QUERY --scope duplicates` retains its query-as-prefix rule when `--file` is absent. |

On MCP, `query` and `patterns` are both wire-optional: source/literals require exactly one nonempty `query` OR a nonempty `patterns` list, all other retrieval scopes require a nonempty `query`, and the `duplicates` audit accepts an omitted query canonically and any legacy query value (empty or nonempty) without treating it as a search pattern. On CLI, the positional query is optional only when repeatable `-e` is present. Validate this after tools/list schema admission, before any file or index access. Repeated patterns are OR, a pipe in a literal remains literal, and a result has one global limit, stable order, one row per location, an accurate `truncated` flag, and the pattern indexes that matched. `--path` uses an exact-file or directory-boundary prefix only for `source`, `literals`, `symbols`, and exact definition; duplicate audits alone use a raw path-prefix match. Reject `--path` for `semantic-code`, `docs`, `memory`, and `knowledge`; it is never a glob. Canonical `source`, `semantic-code`, exact definition, duplicate audit, and call-graph navigation require one selected repository. Accept an explicit `--root REPO` / MCP `root=REPO`, or infer one only when the caller's working directory or declared workspace resolves unambiguously to one store. Add CLI `--root` to `code find`, `dup`, `code calls`, `code callers`, and `code impact` in this proposed contract; those subcommands do not expose it today. For these single-repository tasks, fail closed with a root-selection hint if several repositories are in scope; a multi-root selector fails before reading any file. `literals`, `docs`, `memory`, and `knowledge` may fan out to an explicit repository set; partial or unavailable roots are reported. For `symbols` alone, preserve the MCP wildcard fan-out and the single-root restriction on CLI and MCP comma lists; do not silently reinterpret root syntax. Preserve the existing MCP wildcard symbol ranking/limit and legacy CLI literal multi-root behavior: the latter applies the same limit separately to each selected repository, rejects JSON/CSV across several roots, and searches the working repository rather than nested stores when `--root` is omitted. Canonical new literals/docs/memory/knowledge fan-out uses one global limit and may emit JSON; an old `text`/`strings` invocation does not acquire these new semantics. Do not change an existing `symbols` request merely because its scope spelling is also canonical. Never silently search fewer repositories than requested. New-scope JSON (`source`, `literals`, `semantic-code`, `knowledge`) uses a versioned result envelope stating scope, result unit, coverage, and `complete|partial|unavailable` status. Existing spellings that are also canonical (`symbols`, `docs`, `memory`) cannot select a new shape without an explicit discriminator: preserve their current JSON result shape by default, and add `--search-contract v2` / MCP `contract="v2"` to request the same envelope. Teach this flag only when the agent needs coverage metadata from an overlapping spelling; never imply that an unchanged `--scope symbols --format json` call returns an object rather than its current array. Existing `code find` CLI and daemon RPC symbol results also retain their existing shapes; the new public MCP `code_find` documents its own result separately. An existing request must never change format merely because its scope name is canonical. Legacy JSON retains its old shape and emits a separate machine-readable deprecation notice only for genuinely deprecated forms; validate notice and versioned envelope with consumers before approval. Only the new canonical source-line and AST-literal hit locations use 1-based lines and 1-based UTF-8 byte columns. Existing symbol CLI and daemon/MCP symbol fields carry their current 0-based locations, including CLI JSON/text; do not silently shift them. The new MCP `code_find` reuses symbol locations without rewriting the daemon response. Test the conventions against TUICommander's 0-to-1 display adapter.

## Architecture boundaries

1. Define one typed application request and capability validator under `core`. CLI and MCP convert their inputs into it. Do not place search policy in the CLI parser or MCP schema. Ship the canonical public contract and legacy adapters in one coordinated release; preserve old behavior until the sunset review. Adapt existing search engines in small steps instead of rewriting all storage paths at once.
2. Add a read-only source scanner as a separate engine. Use the established repository root and ignore policy, but do not use the code parser's language filter as the complete text-file filter. Include eligible edited and untracked source. Bound the walk and response. Report unreadable, binary, excluded, or truncated coverage honestly; a partial scan must not claim absence. Guard against symlink escapes and nested stores. Measure the cost before selecting a persistent full-text index.
3. Keep AST literal extraction and indexed symbols separate. An indexed response must say which corpus it used. Replace the global oldest-file hint as a freshness diagnosis. For a definitive indexed answer, reconcile the repository on first open or prove the relevant files current before the answer; otherwise report incomplete coverage instead of a clean no-match. A file-filtered check cannot establish that every eligible file in a directory is current. Use observed file state and successful scan evidence, not the minimum timestamp or a queued hook event. Measure the first-open reconciliation cost before choosing a blocking or asynchronous policy. Prove changed, added, and deleted-file transitions with real E2E tests.
4. Keep renderers and transport adapters separate from the engines. CLI and MCP must agree for new explicit canonical scopes on result positions, matched patterns, limit, and completeness. Canonical `semantic-code` uses the requested limit on both transports; legacy MCP `scope="code"` retains its existing five-result cap while legacy CLI `--scope code` retains its requested limit. Existing symbol search and legacy literal multi-root behavior retain the exceptions stated above. Review the daemon RPC and CLI JSON consumers in TUICommander before release. Do not change the symbol line convention by accident.
5. Update the CLI help and `schema`, the task-first `cheatsheet`, MCP tool field descriptions, `src/mcp/server.rs` base instructions, `src/mcp/dispatch.rs` zero-hit and call-graph hints, `surface`, and the PreToolUse Grep/Bash classifiers from the same capability contract. The current bare-identifier Grep classifier suggests symbols/callers even for an all-occurrences task; a single-file grep, regex, or multi-pattern grep must not be redirected to a narrower corpus. Correct the current `callees` hint to `calls`. Do not instruct an agent to reindex to find a value the selected corpus never stores.
