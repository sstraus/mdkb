# Hook System — Architecture & Operations Guide

mdkb hooks inject memory context into Claude Code / Codex CLI sessions
automatically, without requiring the assistant to call MCP tools. This
document covers architecture, data flow, configuration, and improvement
opportunities.

## Overview

```
Claude Code / Codex CLI
  |
  |-- SessionStart -------> mdkb hook session-start -----> warmup context
  |-- UserPromptSubmit ----> mdkb hook user-prompt-submit -> recall context
  |-- PreToolUse ----------> mdkb hook pre-tool-use ------> CLI suggestions
  |    (matcher: Grep|Bash)
  |-- PostToolUse ---------> mdkb hook post-tool-use -----> watcher channel
       (matcher: Edit|Write|
        NotebookEdit|MultiEdit)
  `-- Stop ----------------> mdkb hook stop --------------> embedding backfill
                                                        `-> optional prior mining
```

Five lifecycle hooks, each with a single responsibility:

| Hook | Trigger | Purpose | Output |
|------|---------|---------|--------|
| **SessionStart** | Session opens | Inject memory warmup so the assistant knows what's stored | `additionalContext` with entry summaries |
| **UserPromptSubmit** | Every opted-in user message | Hybrid-rank memory and docs, then inject relevant entries and graph context | `additionalContext` with matched entries |
| **PreToolUse** | Before Grep/Bash searches | Resolve definition searches from the code index or suggest the precise mdkb command | `additionalContext` with hits or CLI suggestion |
| **PostToolUse** | Edit/Write/NotebookEdit/MultiEdit | Send changed files to the daemon watcher | No output |
| **Stop** | Session episode ends | Backfill pending embeddings; optionally distill a recurring behavioral prior | No output; background work |

## Execution Model

### Command transport: daemon-first with in-process fallback

Every hook command generated by `mdkb setup hooks` is one shell-safe command:

```bash
mdkb hook <event>
```

**Primary path** — `mdkb hook <event>` connects to the daemon via Unix
socket (`~/.mdkb/daemon-hook.sock`). If no daemon is running, it
auto-spawns one (`mdkb serve --daemon`) and retries with exponential
backoff (50, 100, 200, 400, 800 ms — ~1.55s total). The daemon keeps a
`RepoRegistry` in memory, making DB access and FTS queries fast.

**Fallback path** — if delivery provably did not start, the same process opens
an ephemeral `RepoRegistry`, dispatches locally, and returns. It never retries
after the complete request reached the daemon, because the daemon may already
be writing. `[hooks] daemon_required = true` disables the in-process fallback,
including an explicit `MDKB_NO_DAEMON=1`; the hook remains quiet and exits 0.

Hook recall is read-only. Hook-call and optional query telemetry are writers and
therefore take the same project writer-admission lock as daemon mutations,
watcher work, schema initialization, and direct CLI fallback. If either a recall
or telemetry statement reports SQLite corruption, the daemon releases that
repository context immediately so the next request can quarantine, salvage, and
rebuild the index.

The developer telemetry profile keeps this write path opt-in. It correlates
normalized repeated queries with HMAC-SHA-256 under a random per-repository key,
stores no prompt text, records the final eligible recall count and top score,
and removes rows older than the configured retention window during each insert.
Telemetry purge is a typed CLI mutation, so a running daemon remains the sole
SQLite writer.

### Native HTTP/HTTPS transport

The HTTP and HTTPS MCP servers expose `POST /hook/{method}` beside `/mcp` and
route it through the same `dispatch_hook_message` function, `RepoRegistry`,
`DispatchContext`, and in-flight `WorkGate` as the Unix hook socket. The host
sends the lifecycle event object directly; the adapter promotes `cwd` to
`root`, constructs the internal JSON-RPC notification, and returns the same
envelope as Unix dispatch.

Bearer authentication runs before JSON parsing. The token is compared in
constant time, `/health` is the only unauthenticated endpoint, and malformed or
unknown hook methods return JSON-RPC errors with HTTP 200. Both network
transports stop accepting requests before draining in-flight work at shutdown.

Claude Code setup uses native HTTP handlers for UserPromptSubmit, PreToolUse,
PostToolUse, and Stop when `--http-url` is supplied. SessionStart remains a
command hook because that event does not support Claude's HTTP handler. Codex
remains command-based.

### Fire-and-forget contract

Command hooks exit 0 regardless of dispatch errors; failures are logged to
stderr and swallowed so the host CLI is never blocked. HTTP dispatch errors use
a JSON-RPC envelope with status 200, while authentication failures correctly
return 401. When a hook has nothing to contribute, it returns `{}`.

### Matchers

The `PostToolUse` hook entry includes a `matcher` field:

```json
{
  "_managedBy": "mdkb",
  "matcher": "Edit|Write|NotebookEdit|MultiEdit",
  "hooks": [{"type": "command", "command": "..."}]
}
```

This tells Claude Code to only invoke the hook for file-editing tools.
Without it, every tool use (Read, Grep, Bash, Agent, etc.) would trigger
a daemon IPC round-trip just to be discarded by the `REINDEX_TOOLS` check.
SessionStart and UserPromptSubmit don't need matchers — they fire once
per session/prompt by definition.

PreToolUse uses `Grep|Bash`: Bash is needed because agents commonly run `rg` or
`grep` through a shell. The command parser considers only a pipeline's source
stage, so a downstream `| grep` filter is not incorrectly replaced.

## Hook Details

### SessionStart

**Flow:**
1. Check `.mdkbignore-hooks` marker → skip if present
2. Check `.mdkb/` directory exists → skip if absent
3. Read `[hooks]` config → skip if `session_start_enabled = false`
4. Open `Context` (DB connection)
5. Call `get_warmup_index(conn, warmup_limit)` → returns formatted memory
   entry summaries (id, type, title, tags)
6. Build markdown block: `## mdkb memory warmup\n\n- [type] id: title #tags\n...`
7. Write the telemetry row, with the per-phase split (`context`, `warmup`,
   `handoff`, `stale_deps`, `code_check`); if elapsed > `latency_budget_ms`,
   copy it to `hook-slow.jsonl`. Nothing is truncated — the output is bounded
   by `warmup_limit` and `warmup_token_budget`, not by the clock

**Output example:**
```
## mdkb memory warmup

- [problem] fk-violation: Code index FK on reindex #sqlite #foreign-key
- [decision] relative-paths: Use relative paths in index #code-index
```

**What the assistant sees:** This block appears as `additionalContext` in
the session start system reminder. It primes the assistant with knowledge
of what memory entries exist — encouraging MCP tool use for deeper lookup.

### UserPromptSubmit

**Flow:**
1. Extract `prompt` from stdin JSON → skip if empty
2. Check wrap-up markers (`/clear`, `/compact`, `/exit`, `/quit`, `/wrapup`) → skip
3. Check `.mdkbignore-hooks` and `.mdkb/` → skip if absent
4. Read `[hooks]` config → skip if `user_prompt_submit_enabled = false`
5. Require and strip the leading `*` when
   `user_prompt_submit_require_sigil = true` (the default)
6. Build an FTS query: tokenize prompt, strip stopwords (EN+IT), drop tokens < 3
   chars, join with OR, quote each token
7. Embed the raw prompt off the async lock and call
   `search_entries_hybrid_fts` → BM25/vector fusion plus confidence; discard
   entries below `min_recall_score` using the final hybrid score
8. Call `hybrid_search_fts` → matching documents, reusing the same OR query and
   embedding (no second inference pass, no lock held across ONNX)
9. Expand active one-hop memory relations, flag stale dependencies, resolve
   named document neighbors, and suppress repeated results within the session
10. Build markdown: `## mdkb: relevant context` (memory), then
   `## mdkb: matching docs` (search hits), then `## mdkb: related docs`
   (graph neighbors). A doc reachable both ways is emitted once, as a graph
   neighbor — that block carries the relation label
11. If elapsed > `latency_budget_ms`, log to `hook-slow.jsonl`

**Stopword handling:** The filter includes both English and Italian
stopwords (e.g. "il", "della", "perche"). Prompts consisting entirely of
stopwords or short words produce no FTS tokens → hook returns `{}`.

**What the assistant sees:** Relevant memory entries appear as system
reminder context before the assistant processes the prompt. This is
proactive recall — the assistant doesn't need to decide to search.

The separation between relevance and durability matters: topic/problem/decision
confidence does not decay merely because the entry is old, while reminder,
prior, and handoff confidence still reflects time. Prompt admission is then
based on query relevance plus confidence, not age alone.

### PreToolUse

**Flow:**
1. Check `.mdkbignore-hooks` and `.mdkb/` → skip if absent
2. Extract `tool_input.pattern` from stdin JSON → skip if empty
3. Classify pattern:
   - Pure identifier (single word, no regex metacharacters) → suggest
     `mdkb search --scope symbols "{pattern}"`
   - Definition search (`fn X`, `func X`, `def X`, `class X`, etc.) →
     suggest `mdkb code callers {name}`
   - Callsite pattern (`name(`) → suggest `mdkb code callers {name}`
   - Other → return `{}`
4. Resolve binary path via `std::env::current_exe()`
5. Build suggestion: `Use '{binary} search --scope symbols "{pattern}"'
   or '{binary} code callers {pattern}' via Bash.`

**Matcher:** `Grep|Bash` — direct Grep calls and shell-based recursive
`grep`/`rg` searches trigger this hook; downstream pipeline filters do not.

**What the assistant sees:** A suggestion to use mdkb CLI commands
instead of (or in addition to) Grep. Works without MCP — the suggestion
references the CLI binary directly.

### PostToolUse

**Flow:**
1. Check `post_tool_use_enabled` config → skip if false
2. Check `tool_name` against `REINDEX_TOOLS` (`Edit`, `Write`, `NotebookEdit`,
   `MultiEdit`) → skip if not in list
3. Extract file path from `tool_input.file_path` or `tool_input.notebook_path`
4. **Security:** `canonicalize_under_cwd()` resolves the path and verifies it's
   strictly under the working directory. Path traversal attempts
   (`../../etc/passwd`) are rejected with a warning
5. Send path to `handle.reindex_tx` (daemon watcher channel) for immediate
   reindex

**Reindex mechanism:** The daemon's file watcher receives the path on its
channel and triggers a targeted reindex. No intermediate queue file is
involved.

**Output:** `{"queued": true}` on success, `{}` when skipped —
PostToolUse must never inject context.

### Stop

**Flow:**
1. Schedule a single-flight embedding backfill for memory rows written while
   the local model was unavailable
2. Return immediately when prior mining is disabled (the default), or when no
   external `distiller_program` is configured
3. Read a bounded transcript tail and launch the external distiller in a
   detached task
4. Recurrence-gate and promote reusable lessons as 30-day behavioral priors

The hook always returns `{}`. Mining never runs an undocumented built-in LLM,
and disabling new mining does not disable injection of already promoted priors.

## Configuration

All settings in `.mdkb/config.toml` under `[hooks]`:

| Key | Type | Default | Notes |
|-----|------|---------|-------|
| `session_start_enabled` | bool | `true` | Disable warmup injection |
| `user_prompt_submit_enabled` | bool | `true` | Disable recall injection |
| `pre_tool_use_enabled` | bool | `true` | Disable Grep/Bash interception and indexed hits |
| `post_tool_use_enabled` | bool | `true` | Disable reindex-on-edit notifications |
| `warmup_limit` | usize | `10` | Max entries in SessionStart warmup |
| `warmup_token_budget` | usize | `300` | Approximate hard budget for complete warmup lines |
| `warmup_min_confidence` | f64 | `0.25` | Confidence floor for warmup entries; `0` disables it |
| `recall_limit` | usize | `5` | Max hybrid memory results in UserPromptSubmit |
| `recall_docs_limit` | usize | `3` | Max matching documents in UserPromptSubmit; `0` = memory only |
| `latency_budget_ms` | u64 | `200` | Overrun threshold; logs to `hook-slow.jsonl` |
| `min_recall_score` | f64 | `0.3` | Floor on the final hybrid relevance-plus-confidence score |
| `user_prompt_submit_require_sigil` | bool | `true` | Require a leading `*` before prompt recall |
| `daemon_required` | bool | `false` | Disable the in-process command-hook fallback |
| `code_hits_in_pretooluse` | bool | `true` | Return indexed definition hits before suggesting a command |
| `doc_graph_in_recall` | bool | `true` | Add bounded one-hop document neighbors to recall |

## Opt-out Mechanisms

From most to least granular:

1. **`.mdkbignore-hooks` marker file** — place at repo root. All hooks
   return `{}` for any CWD under this marker. Searched upward to `$HOME`.
2. **Per-event toggle** — configure the four synchronous hook toggles in
   config.toml; Stop mining is independently disabled by default under
   `[priors]`.
3. **Disable at install** — `mdkb setup hooks claude --disable post-tool-use`.
4. **Uninstall** — `mdkb setup remove hooks claude|codex`, or remove
   hook entries from settings file manually.

## Observability

- **`mdkb stats`** — shows `HooksSummary` with `slow_events_7d` (hooks
  that exceeded latency budget in last 7 days).
- **`.mdkb/hook-events.jsonl`** — one line per hook invocation, with event
  name, outcome (ok/empty/error), elapsed time, and latency budget.
- **stderr** — all internal errors are logged via `tracing::warn`.

## Security

- **Path traversal protection** — `canonicalize_under_cwd()` resolves
  symlinks, collapses `..`, and rejects any path that escapes the working
  directory. On macOS, handles `/tmp` → `/private/tmp` symlink resolution.
- **Shell injection protection** — `hook_command_line()` uses single-quote
  escaping for the binary path, neutralizing `$()`, backticks, and
  metacharacters.
- **FTS injection protection** — each search token is double-quoted to
  neutralize FTS5 operators embedded in user prompts.

## Content-selection invariants

- Recall uses hybrid relevance and a configurable final-score floor.
- Durable knowledge is not penalized for age; lifecycle records are.
- Warmup ranks by project affinity and access, applies a confidence floor and
  token budget, and reserves at most one slot for a curated prior.
- Repeated prompts do not reinject the same memory into one session.
- Expansion is bounded and only active, resolvable graph neighbors surface.
- ONNX inference runs outside the repository lock, and document recall reuses
  the memory query embedding.
