## Reality contract (before production changes)

- Effect: a CLI or public MCP source search returns current eligible file lines, matching OR-pattern indexes, a stable global limit, and a coverage status. A legacy invocation still returns its old corpus and output shape. An indexed negative states its corpus and verified freshness or reports uncertainty.
- State: source lines come from the repository file system through the shared ignore policy; literals and symbols come from `.mdkb/code.sqlite`; docs and memory come from the existing store. A queued watcher or hook update is not proof that the index changed.
- Outside world: the file system may change during the walk; gitignore and symlink behavior comes from the `ignore` crate, not from a fabricated fixture. The daemon and TUICommander use the observed existing 0-based symbol wire locations. The source walk is not an atomic snapshot.

## Risk and boundaries

High risk: this changes a shared CLI/MCP protocol, index-freshness claims and live filesystem reads. The release cannot be called complete until real CLI/MCP examples, existing JSON clients and TUICommander consumers are checked. Existing unrelated worktree changes are not part of this story. Do not commit or push without separate authorization.

## Adjacent scenarios and named defects

- Edited, added and deleted files: catches a stale-index result that falsely asserts current absence; a live source search must read the current tree.
- Repeated or overlapping patterns on a line versus two separate AST nodes on that line: catches deduplication at the wrong result unit or a per-pattern limit.
- Ignored, unreadable, binary, symlinked and nested-store files: catches a complete-negative claim after a partial or escaped walk.
- A pattern containing `|` without `--regex`: catches accidental regex semantics; explicit source-only regex must use its own path.
- Legacy multi-root symbol and literal requests, ignored MCP filters and duplicates queries: catches compatibility drift caused by shared canonical scope names.
