Repository memory for coding agents.

mdkb gives Claude Code, Codex and any MCP client one retrieval layer for the repository: what the team decided, what the docs say, and what the code does. It finds the part that matters for this prompt, so the agent does not load the whole repository every turn.

01

The difference

A notes file grows. A memory should select.

The usual agent memory is a file of notes that loads into every prompt, or a store of chat snippets that a tool call may or may not search. Both grow, both keep wrong notes, and neither knows the code. mdkb ranks what the repository knows against each prompt and sends only the part that matches.

Typical agent memory mdkb
Scope What was said in a conversation. The repository: docs, decisions, solved problems, symbols and call edges, searched as one context.
Cost The whole file in every prompt. It grows forever. Hybrid BM25 + vector ranking against the prompt. Only matching entries are injected.
Staleness A wrong note stays until a person finds it. Entries are superseded, refuted or confirmed by evidence. Reminders, priors and handoffs decay with age.
Trust No source, no history. Provenance, source-authority weight, Bayesian confirmation signal, revision diffs, typed edges.
Recall Depends on the agent deciding to call a tool. Hooks inject context at session start, on every prompt, and around tool calls.
Code Not covered. tree-sitter index for 14 languages: callers, callees, impact, duplicates, hidden coupling.
Where it lives Often a hosted memory API or vector service. One local Rust binary. SQLite, on-device embeddings. Durable memory exported as Markdown for Git review.
Proof Rarely measured. mdkb eval fails CI below a recall floor; mdkb stats reports hit rate and latency.
02

Recall without a tool call

Context arrives at the moment it is useful.

Lifecycle hooks for Claude Code and Codex run through one dispatcher (command hooks, a Unix socket or native HTTP). The agent does not have to remember to ask.

03

Hybrid retrieval

Exact words and meaning, fused, then one hop further.

Hook recall and mdkb search use the same score. Full-text search catches identifiers and error strings; on-device embeddings catch paraphrase. Typed memory edges pull in the entry that supports the hit, and flag it when its support was superseded.

04

Memory that ages by evidence

Not by the calendar. Not by accident.

Durable knowledge stays valid until something proves it wrong. Session state fades on its own. Every change is explicit, and near-duplicates are rejected at write time.

05

A self-learning loop

It learns from its own sessions.

Off by default. When on, each lesson must earn its place.

  1. At Stop, mdkb reads the episode that just ended.
  2. It detects an error that was fixed, or a correction from the user.
  3. A configured local or remote CLI distils one falsifiable lesson with a machine-matchable trigger.
  4. Lessons that recur across sessions are promoted to priors.
  5. Priors are injected where their trigger fires, then settled as confirmed or refuted at the next Stop.
06

Structural code intelligence

Know what breaks before you change it.

tree-sitter indexes 14 languages into persistent symbols and typed edges. Calls resolve through a tiered cascade that keeps the receiver type, so store.write() and cache.write() are different edges, and an unresolved call says so instead of inventing one.

Callers, callees, impact

Edges for Calls, Uses, Implements, Expands and Defines, with a resolution tier on every call.

mdkb code callers NAME
mdkb code impact NAME --depth 2

What the repo says twice

A structural duplicate report, bucketed by how trustworthy each finding is. No model needed.

mdkb dup --since main

Hidden coupling

Files that change together in Git with no confidently resolved call edge between them.

mdkb coupling --min-cochanges 3
07

Retrieval you can measure

Numbers from commands, not from adjectives.

Eval with a floor

mdkb eval scores memory search against a held-out fixture and fails CI below a floor.

Hook statistics

mdkb stats reports hook activation, hit rate, latency and mining outcomes.

Private telemetry

An opt-in developer profile records recall quality without storing prompt text. It stays on the machine.

08

Quick start

Three steps, one binary.

The embedding model downloads on first use and then runs on-device. No memory API, hosted vector database or LLM extraction service is required.

1 · Install

brew install sstraus/tap/mdkb
# or, from a checkout
cargo install --path .

2 · Index a repository

cd your-project
mdkb init
mdkb collection add docs ./docs
mdkb update

3 · Connect the agent

mdkb setup mcp claude --scope local
# then restart Claude Code

Pre-built binaries for macOS, Linux and Windows are on GitHub Releases. Hooks, priors and every command are documented in the README.
