# Session Summary

This session focused on improving Claude Code's discovery and adoption of mdkb MCP tools through four implementation steps plus code review.

## What Was Accomplished

The core problem: Claude Code's MCP Tool Search defers all tools when aggregate tool count exceeds ~10% of context. mdkb tools were invisible because server instructions described *what* tools do, not *when* to use them. The solution had four parts:

1. **Rewrote BASE_INSTRUCTIONS** in `src/mcp/server.rs` — reframed as "WHEN to load mdkb" triggers rather than neutral descriptions. Reduced size ~40% and made it explicit that users should search for mdkb tools first.

2. **Made tool descriptions directive** — `search()`, `memory_write()`, and `code_graph()` now start with action words: "Use this tool BEFORE Grep...", "IMPORTANT: Call this after...", "Call this BEFORE refactoring...".

3. **Added `.claude/rules/mdkb.md` generation** on `mdkb init` with `--rules-dir` parameter support. This puts reinforcement directives directly into Claude Code's system prompt for every session in that project — the most impactful adoption mechanism. Handles multi-repo use cases by supporting custom rules directories and absolute paths.

4. **Implemented MCP Prompts capability** — added `/mcp__mdkb__prime` prompt that gathers index status, recent memories, and code index stats to prime Claude at session start.

## Key Decisions Made

- **Multi-agent support via `--rules-dir`**: Accounts for opencode, openrouter, and other CLI agents that may use different rules directories. Auto-detects `.claude/` in project root but allows explicit paths.
- **Path traversal intentional for multi-repo**: Boss clarified that mdkb is used across different project roots, so `--rules-dir` ability to write outside project root is by design, not a bug. Added documentation to explain this.
- **Separate impl block for prompt handlers**: rmcp's `#[tool_router]` macro conflicts with custom methods, so prompt handlers live in a separate `impl McpServer` block.

## Problems Encountered and Solved

1. **rmcp type paths**: Initial attempts to import `RequestContext` from `rmcp::handler::server` failed — correct path is `rmcp::service::RequestContext`.
2. **`ListPromptsResult` missing field**: The `paginated_result!` macro generates a `meta: Option<Meta>` field that wasn't being initialized.
3. **25+ `handle_init` call sites needed updating**: All existing test and handler calls passed 1 argument; changed to 2 with systematic `replace_all` edits.
4. **Test assertion updates**: Three tests failed after rewriting instructions because they asserted "Local Knowledge Base" but new text says "Project Knowledge Base".
5. **Prompt handler errors**: Initially discarded errors silently. Fixed all `if let Ok(...)` patterns with `match` + `tracing::warn!`.
